# 덱설계: 재료 → 덱설계 JSON → 덱

앱: 이 저장소의 맨 위 폴더 (아래 명령은 이 폴더에서 돌린다)
꼭 먼저 읽을 것: `덱설계_쓰는법.md` (장 종류·칸·한도·글 쓰는 규칙). 스키마: `덱설계.schema.json`.

## 순서

1. **무엇을 위한 덱인지 확인한다.** 듣는 사람, 발표 시간, 꼭 말할 결론. 메모에 있으면 묻지 않는다.
2. **재료 넣기**
   ```
   python 재료넣기.py <덱이름> <메모.md> <데이터.xlsx> <회의록.pdf> <사진.tif> ...
   ```
   → `프로젝트/<덱이름>/재료요약.md` 를 끝까지 읽는다(글 덩어리, 표 경로·머리, 그림 경로·크기).
   필요하면 `재료/<아이디>/표/*.json` 을 열어 숫자를 확인한다. 숫자는 재료에 있는 것만 쓴다.
3. **덱설계 JSON 쓰기**: `프로젝트/<덱이름>/덱설계.json`
   - 흐름은 쓰는법 7장(표지 → 결론 한마디 → 왜 → 한 것 → 본 것 → 숫자 → 결론·다음 → 끝)을 바탕으로 재료에 맞춘다.
   - 제목은 결론 문장, 한 장 한 메시지, 이름표 글 금지, 숫자에는 단위와 비교 대상.
   - 연구자가 확실하지 않다고 한 것은 단정하지 않는다. 결론 장의 `다음`과 노트에 남긴다.
   - 장마다 `노트`(말로 덧붙일 이야기)를 쓴다. `발표분`을 적는다.
   - 경로는 재료요약의 것을 그대로. 없는 그림은 쓰지 않는다.
4. **굽고 점검**
   ```
   python 덱만들기.py <덱이름>
   ```
   - `[멈춤]` 이 있으면 JSON을 고쳐 다시. `[주의]`(글자 수, 대비, 해상도)도 되도록 고친다.
   - 결과의 `<덱이름>_그림묶음.zip` 안 PNG(또는 `그림/` 폴더)를 **직접 열어 본다**: 넘침, 빈 곳, 사진이 잘렸는지, 도표가 읽히는지.
5. **넘기기**: 결과 폴더 경로, 감독관이 남긴 주의, 노트에 적은 '아직 모르는 것'을 짧게 알린다.
   사람은 `켜기.bat` 화면에서 글을 고치고 테마·꾸밈을 고른다(꾸밈은 사람이 고른다. JSON에 쓰지 않는다).

## 하지 말 것

- 재료에 없는 숫자·결과를 만들지 않는다.
- 사용자 파일(받은 자료, v1 PPTX)을 고치거나 지우지 않는다. 재료넣기는 복사본을 푼다.
- 그림을 다시 저장하거나 줄이지 않는다(원본 그대로 PPTX에 들어간다).
- v1 PPTX를 고치는 일(v2 만들기)은 화면의 '새 덱 → PPTX v1에서 시작'으로 한다.
